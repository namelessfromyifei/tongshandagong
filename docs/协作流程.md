# 协作流程（Fork + Pull Request）

本项目采用 GitHub 开源协作流程：**外部贡献者先 fork 仓库到自己账号，在自己的副本上开发，再通过 Pull Request（PR）请求合并回上游仓库。**

维护者负责审查 PR 并合并；贡献者推送代码只需要自己 fork 的写权限，不需要上游仓库权限。

---

## 一次性配置

```bash
git clone git@github.com:<你的账号>/tongshandagong.git   # 或先 clone 上游再添加 fork remote
cd tongshandagong

git remote add upstream git@github.com:zhanghan4141-oss/tongshandagong.git
git remote -v
```

推荐 remote 命名：

| remote | 指向 | 用途 |
|---|---|---|
| `origin` | 你自己的 fork | 日常推送 |
| `upstream` | 官方仓库 | 同步最新代码、发起 PR 的目标 |

如果已经 clone 了上游仓库，把上面的 `origin`/`upstream` 互换即可。

---

## 日常开发流程

```bash
# 1. 同步上游最新代码
git checkout main
git pull upstream main

# 2. 从 main 创建功能分支（不要直接在 main 上改）
git checkout -b feature/简述功能

# 3. 开发、提交
git add -A
git commit -m "简述这次改动"

# 4. 推送到自己的 fork
git push -u origin feature/简述功能
```

推送后打开 GitHub 上你的 fork 页面，点击 **Compare & pull request**：

- Base repository：`zhanghan4141-oss/tongshandagong`，base 分支：`main`
- Head repository：你的 fork，compare 分支：`feature/简述功能`
- 填写标题和说明（改了什么、为什么改、如何验证）
- 点击 **Create pull request**

维护者审查 diff 后合并，合并方式默认 **Squash and merge**（历史更整洁）。

---

## 合并后清理

```bash
git checkout main
git pull upstream main        # 拉取已合并的改动
git branch -d feature/简述功能 # 删除本地分支
```

fork 页面上可点击 **Delete branch** 删除远端分支。

---

## 常见问题

- **推送被拒（Permission denied / 403）**：说明推的不是自己的 fork，检查 `git remote -v`，或确认 SSH 密钥绑定的 GitHub 身份。
- **PR 显示冲突**：上游改动与你的分支冲突，先 `git pull upstream main` 合并进功能分支并解决，再推送。
- **分支落后于上游**：GitHub fork 页面点击 **Sync fork**，或本地按上面的"合并后清理"同步。
- **提交作者信息**：由本机 `git config user.name/user.email` 决定，与推送使用哪个账号无关；邮箱建议使用 GitHub 账号已验证的邮箱，提交才能正确关联。
